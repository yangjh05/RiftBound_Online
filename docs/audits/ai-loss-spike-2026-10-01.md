# 201회차 이후 손실 상승 진단

대상은 `adaptive-policy-q-public-review-20260929`의 200~208회차입니다. 사용자 질문에 따라 로그와 실제 고정 실행 코드만 확인했으며 학습·평가·모델을 변경하지 않았습니다.

## 손실 정의가 달라진 상승

`joint-policy-learning-protocol.json`의 `afterIteration: 200`, `rehearsalCoefficient: 0.25`에 따라 201회차부터 총손실에 검증된 훈련용 교정 사례의 선택 손실이 추가됩니다. 기존 PPO 항목과 복습 항목을 합산한 숫자가 `meanLoss`입니다. 따라서 전후 총손실을 같은 척도로 직접 비교할 수 없습니다.

현재 실행 코드의 가중치(행동 1, 상태 가치 0.5, 행동 가치 0.25, 진단 0.05, anchor 0.05, entropy -0.01)와 기록된 항목으로 분해했습니다. 아래 복습 기여량은 총손실에서 기존 항목 합을 뺀 재구성 값이며 반올림했습니다. 해당 회차들의 teacher·belief 손실은 0입니다.

| 회차의 마지막 시도 | 기존 항목 | 추가 복습 항목 | 총손실 | 해당 시도 반영 |
| --- | --- | --- | --- | --- |
| 200 | 0.146 | 0 | 0.146 | 거부 |
| 201 | 0.121 | 0.259 | 0.379 | 반영 |
| 205 | 0.241 | 0.277 | 0.518 | 거부 |
| 208 | 0.184 | 0.277 | 0.461 | 거부 |

대시보드 `server/training-dashboard-data.mjs`는 회차별 마지막 `candidate-policy-training` 이벤트의 meanLoss를 표시하면서 합산 항목 변경 및 accepted 여부를 구분하지 않습니다. 거부 후 롤백된 시도의 수치도 그래프에 나옵니다. 현재 그래프 상승을 배포 모델 성능 하락이나 가중치 폭주로 해석해서는 안 됩니다. 관련 로그는 수치 유한성 검사를 통과했고 최근 네 회차의 평균 기울기 크기는 약 1.44~1.66입니다.

## 별도로 확인한 PPO 갱신 병목

- 201·202회차: 각각 4개 epoch 반영.
- 203회차: 3개 반영, 4번째 거부.
- 204회차: 1개 반영, 2번째 거부.
- 205~208회차: 각각 첫 epoch에서 거부, 반영된 PPO epoch 0개.

203회차 마지막 시도부터 반복되는 거부 사유는 같은 검증용 멀리건 사례 한 개의 기존 정답을 잃는 `previously-correct-choice`입니다. 201회차 고정 lesson bank의 validation 인덱스 27, `supply:201:origins-leona:opening:1`입니다. 업데이트를 1/64로 줄여도 최근 네 회차 모두 통과하지 못했습니다. 훈련용 사례 보존 검사는 통과했고 검증용 사례에서 막혔습니다.

이는 프로세스 중단이나 수치 폭주가 아니라, 교정 보존 조건과 PPO 변화가 충돌하여 업데이트를 되돌리는 문제입니다. 학습 자료 수집은 계속되지만 PPO 결과가 최근 네 회차에서 반영되지 않았습니다. 다른 학습 단계까지 전부 멈췄다고 확장 해석하지 않습니다.

다음 보완에서는 손실 구성과 채택·거부를 따로 보여주고, 정당한 교정 사례의 기준을 유지하면서 학습 갱신 병목을 해결해야 합니다. 이 검증 사례를 훈련으로 옮기거나, 평가 정답을 직접 학습시켜 검증을 통과시키는 방법은 사용하지 않습니다. 전체 성능 향상 여부는 별도 고정 모델 승급평가로 확인해야 합니다.
