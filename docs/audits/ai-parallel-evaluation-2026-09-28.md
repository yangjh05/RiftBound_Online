# 평가 병렬화 및 챔피언 평가 우선 처리

## 원인과 변경

기존 평가는 별도 프로세스 하나에서 모든 경기를 순차 처리했다. 75번 평가는 1414세대 대 183세대 전술 기준 모델 비교이며, 이 평가가 끝날 때까지 최신 모델 대 현 챔피언 비교도 시작하지 못했다. 당시 최근 80경기는 경기당 약 66.8초였다.

새 `parallel-evaluation-protocol.json` 이후의 평가는 최신 대기 후보와 현재 챔피언을 비교한다. 기존의 매 다섯 번째 전술 기준 모델 평가 예약은 이후 예약에 적용하지 않는다. 기존 요청·통계 계획·완료 경기·시작된 예약은 변경하지 않는다. 기존 75번 평가는 별도 보존 큐에서 저장된 564경기를 이어서 처리한다.

새 평가는 기존 혼합 매치업 평가기의 8경기 블록을 네 프로세스에 분배한다. 모델·게임 엔진·시드·덱 배정·선후공·양측 판단 깊이(후보 4개, 미리보기 48회)는 동일하다. 각 결과를 원래 경기 번호로 즉시 저장하며, 통계 판정은 예정된 전체 매치업 회차가 완성된 뒤에만 한다. 저장 순서가 뒤섞이거나 일부 경기만 남아도 누락 경기만 계산한다. 완료가 빠른 경기만 골라 승급을 판정하지 않는다.

전체 16개 배정에는 학습 제어 1, 새 평가 제어 1, 새 평가 계산 4, 기존 평가 1, 교정 분석 3, 자가대전 6이 포함된다. 기존 평가가 끝나면 자가대전이 7개까지 늘어난다. 교정 분석의 유휴 자원을 빌리는 기존 로직도 이 한도 안에서 유지한다. 우선순위는 Normal을 유지한다. 평가가 빨라지는 대신 자가대전·교정 분석 처리량 일부를 사용한다.

## 중단 및 재개 무결성

- 평가 요청에는 별도의 실행 프로토콜 해시를 기록한다. 기존 통계 계획과 검증 기준을 재작성하지 않는다.
- 각 계산 워커가 동결된 모델 해시, 실행 엔진 지문, 덱 적법성, 평가 검토기 구현을 검사한다.
- 제어 프로세스는 경기 번호·요청 해시·검토기 해시를 검사하고 파일을 원자적으로 저장한다.
- 결과 파일을 만들었더라도 평가 제어·계산 워커가 종료될 때까지 슬롯을 반환하지 않는다.
- 평가 제어 프로세스가 중단된 경우 남은 워커 잠금을 확인하고 같은 슬롯이 해제된 후 재개한다.
- 학습 run과 모델을 새로 만들거나 기존 자료를 삭제하지 않는다. 학습은 체크포인트 경계에서 전환한다.
- 교정 장면의 정답 판정, 학습/검증 분리, 승급 통계 기준은 변경하지 않는다.

## 검증 및 실행본

관련 자동 검증 66개 통과: 기존 평가 무결성·혼합 매치업·중간 판정·양측 검토기·워크풀 용량·새 병렬 스케줄링/IPC 오류 처리.

대시보드 관련 검증도 16개 통과하여 총 82개를 확인했다. 결과 파일이 번호 순서대로 생성된다는 가정을 제거했다. 승급 전망에는 완성된 연속 경기 묶음만 사용하고, 처리 속도는 실제 완료 시간 순서로 계산한다. 같은 시각에 여러 경기가 완료되어도 모두 처리량에 포함한다. 경기 파일을 읽으며 확인한 수정 시각을 재사용하므로 추가 파일 조회도 줄였다.
