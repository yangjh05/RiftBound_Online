# 학습과 승격을 분리한 Policy–Q 반복 과정

2026-09-14. 실행 계약: `continuous-policy-q-experiments-v1`.

## 변경한 이유

기존 Shadow의 자연 분포 85경기/전체 119경기 및 결정적 사례 47경기라는
유효 표본 계획을 후보 학습의 선행 조건으로 사용하면 희귀 상황 때문에 모든
학습이 장기간 멈춥니다. 이 수치는 해당 상황의 성능을 주장하는 데 필요한
자료 계획으로 유지하고, 새 실행에서는 후보 학습을 시작하는 조건에서 분리합니다.
기존 엄격한 인증 절차 자체를 통과했다고 표시하지 않습니다.

## 실행 경로

`npm run train:adaptive -- <config.json>`으로 `scripts/train-adaptive-policy-q.mjs`를 실행합니다.
모델, 자료, 감사, 평가 상태는 실행별 `adaptive-policy-q` 하위에 저장합니다.

1. 기존 Training 내부의 고정 분할을 그대로 읽습니다. Validation 및 고정
   Anchor는 학습에 합치지 않으며 Development/Confirmation/Final Audit를 열지 않습니다.
   초기 64경기의 증거로 구조를 학습하고, 이후 반복마다 기존 96경기와 새 감사
   증거 최대 32경기를 순환 사용합니다. 전체 원본은 유지됩니다.
2. 현재 실험용 정책을 고정하여 새 경기 32개를 수집합니다. 오래된 경기의
   정책 확률을 새 PPO의 확률처럼 취급하지 않습니다. 경기 파일은 완료 즉시 저장하고,
   재개 시 완료한 경기 번호를 건너뜁니다.
3. PPO 4 epoch로 배우를 갱신합니다. Q의 상태 가치와 일반 행동/멀리건 행동
   head는 별도 증거로 학습합니다. 후자의 새 보조 학습은 기록으로 확인한
   **heuristic continuation의 Shadow Q**입니다. 변화하는 배우의 인증된
   Policy-Q로 간주하거나 배우의 행동을 강제로 바꾸는 권한을 부여하지 않습니다.
   승패가 같은 seed도 회귀에 포함하며, 개별 seed의 승패 차이를 확정적인
   행동 순위로 학습하지 않습니다. 실전 배우는 PPO를 통해 바뀝니다.
4. 후보 체크포인트를 고정한 뒤 별도 프로세스에서 현재 챔피언과 실제 게임을
   평가합니다. 판정 불충분 시 챔피언을 유지하고 다음 후보 학습을 계속합니다.
   2026-09-15부터 진행 중인 평가 1개를 고정하고, 대기 후보는 가장 최근 저장한
   후보로 갱신합니다. 실제 시작 직전에 상대·seed·판정 예산을 예약합니다.
   예약 중 중단돼도 같은 예약을 복구하며, 시작하지 않은 이전 후보도 파일로 남깁니다.

## 정밀 계산과 저장 상태

긴 마지막 검사를 자기대전 안에서 수행하는 대신, 합법적인 실제 경기에서
원래 관찰, 본인의 기억, 후보 행동과 정확한 의사결정 위치를 저장합니다.
히든 정보는 기존 paired determinization으로 샘플링하며 실제 상대 손패를
배우에게 입력하지 않습니다. 데이터는 전부 로컬에 보관합니다.

감사는 별도 공용 풀에서 4개 seed씩 계산하고 완료한 조각을 저장합니다.
32→64→128을 기본으로 하고 경기 전에 정한 일부 작업만 512/1024까지
허용합니다. 관측 시점과 전체 seed 은행을 먼저 저장하고, 가족 신뢰도 99%를
예정된 관측 횟수에 Bonferroni로 나눕니다. 작은 관측 차이는 동등성으로
간주하지 않으며, 예산 소진 시 불확실성을 그대로 남깁니다.

원본 파일 hash, continuation, 정보 집합, seed, 원래 경기 ID와 step 위치가
일치해야 결과를 사용할 수 있습니다. 라벨은 sidecar에 쓰며 원본을 바꾸지
않습니다. 같은 상태의 복제나 seed 수를 독립 경기 수로 세지 않습니다.
워커는 특정 감사가 끝날 때까지 전체 작업 묶음을 기다리지 않습니다.

## 실전 평가의 해석

서로 다른 seed의 8경기 블록 안에서 좌석·선공·무작위 흐름을 교환합니다.
블록 전체 평균을 독립 관측 하나로 취급합니다. 기본 128블록, 즉 1,024경기에서
한 번만 승격을 판단합니다. 후보마다 `0.05 / (n × (n+1))`의 유의수준을
미리 배정하므로 반복 후보의 총 오승격 확률 상한은 5%입니다.
Hoeffding 하한이 승률 50%를 넘어야 합니다. 각 덱 최소 8블록 및 덱/좌석
관측 승률 40% 이상을 별도 회귀 방지 조건으로 둡니다. 이는 모든 희귀
상황의 우위를 입증하는 조건이 아닙니다. 미완료·판정승·불법 행동 경기가
있으면 승격하지 않습니다. 외부에서 챔피언이 바뀌면 오래된 평가로 덮어쓰지 않습니다.

## 자원과 재개

정상 시 자기대전 최대 8, 정밀 감사 최대 6, 평가 1, 학습 1로 계산 슬롯
총 16개 이내를 유지합니다. 자기대전/감사는 기존 메모리 기반 증감 로직을
사용하며 High 우선순위를 유지합니다. 기존 긴 경기에는 벽시계 제한을
추가하지 않습니다. 전환 시 기존 워커는 새 경기를 받지 않고 현재 경기를
끝내며, 남은 기존 워커 수만큼 새 실행의 여유를 줄입니다.

2026-09-15 보완: 기존 워커가 전부 끝날 때까지 감사와 평가를 막던 조건을
제거했습니다. 빈 슬롯 3개부터 평가, 4개부터 감사도 시작합니다. 이후 자기대전을
8개까지 늘리고 감사에 남은 슬롯을 배정합니다. 예를 들어 기존 워커 3개가 남으면
자기대전 8 + 감사 3 + 평가 1 + 학습 1, 기존 워커 1개가 남으면 감사가 5개가 됩니다.
기존 워커가 줄어드는 동안 각 부문의 할당은 줄지 않으므로 실행 중인 다른 부문의
슬롯을 빼앗지 않습니다. 감사 풀도 현재 공유 한도를 주기적으로 읽어 증감하며,
축소 시 진행 중인 seed 조각을 마친 뒤 종료하고 완료 자료를 유지합니다.
`audit-progress.json`에는 실제 감사 워커와 현재 한도를, 평가별 `progress.json`에는
완료한 평가 경기 수를 저장합니다.

경기, 감사 조각, PPO epoch, 평가 경기, 후보와 평가 예약 번호가 저장됩니다.
Q 갱신 도중 중단되면 그 작은 Q 갱신을 다시 수행합니다. OS 재부팅 후에는
예전 PID 번호를 새 프로세스의 소유권으로 오인하지 않습니다.

## 호환성 및 검증

기존 기본 실행의 행동/학습 목표는 유지되고, 새 동작은 명시적 옵션으로만
켜집니다. 기존 leaf 계약 1–4를 계속 검증하고 새 progressive 계약 5를
추가했습니다. 전체 원문 digest가 정확히 일치하는 경우만 이전 엔진
fingerprint로 연결합니다. 이후 소스 변경은 다시 검토해야 합니다.

집중 검사: 학습/승격 분리, 전체 16개 제한 및 전환 중 중복 할당,
블록 단위 판정과 반복 검정 예산, 미완료 경기 거절, 상태 복제 중복,
seed 조각 재개 및 잘못된 seed 거절, 자료 원본 보존, Shadow Q 권한 경계,
기존 신경망 격리/증거 계약 회귀. 실제 기존 자료 32경기의 시험 학습에서
유효 증거 38개로 유한한 loss를 얻었고, 학습 1,384경기/검증 345경기의
겹침이 0임을 확인했습니다. 이것은 실력 향상을 입증하는 결과가 아닙니다.

후속 엄격 검증에서는 기존 실행의 분할 재배정 오류를 복원하고 66회차까지의
학습 계획, 2,112경기, 후보 66개를 검사했습니다. 현재 고정 목록은 학습 1,398경기,
내부 검증 349경기입니다. 세부 결과와 64~66회차 검증 점수의 대체 기록은
[2026-09-15 검증 기록](ai-adaptive-integrity-2026-09-15.md)을 참고합니다.
