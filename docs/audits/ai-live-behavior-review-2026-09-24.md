## 주사위를 이기고 선공을 넘기는 이유

- 그러나 현재 학습은 `bestOfThreeFraction:0`이며 (`scripts/train-adaptive-policy-q.mjs:647`), `selfplay.mjs:366`에서 선공을 미리 정한 게임을 생성한다. 선후공 균형 대전은 선후공 **선택**을 훈련하는 것과 다르다.
- 완료된 247회차 32경기 5,060개 학습 step을 직접 읽었고 `chooseFirstPlayer`는 **0개**, `confirmFirstPlayer`는 32개였다. 현재 승급 평가 역시 미리 배정된 선공으로 시작한다.
- 운영 배포 아카이브에서 추출한 encoding/model의 SHA-256이 실제 서버 파일과 일치함을 확인하고, 실제 공개 714세대 체크포인트로 카이사 미러전의 주사위 승리 상태를 재현했다. AI 자신의 주사위 행동에 따른 순환 신경망 기억도 포함했다. 실행 온도는 실제 대전과 같은 0.22였다. Node에서는 JS CPU TensorFlow 경로로 계산했으므로 브라우저 수치와 미세 차이는 가능하다.
- 재현 상태에서 AI가 p2일 때 **p1 선공 확률 94.97%, 자기 선공 확률 5.03%**였다. AI를 p1에 놓으면 p1 선공 확률 99.15%였다. 이는 이 재현 상태의 모델 선택 확률이며 실전 전체의 관측 빈도가 아니다.
- 따라서 '후공 이득을 검증해 선택한 전략'으로 해석할 근거가 없다. 선후공 선택에 대한 훈련·검증이 빠진 상태에서 p1 선택 편향을 내고 있는 것이다. 982세대도 같은 운영 코드의 p2 재현 상태에서 자기 선공 55.00%에 그쳐 모델 파일 교체만으로 해결된다고 볼 수 없다.

## 보완 우선순위

1. 운영 대전의 모델 세대와 로컬 승급 모델을 연결하고, 실제 내려받는 모델의 세대·행동 버전을 확인한다. 호환성 검사 없이 파일만 교체하지 않는다.
2. 선후공 선택을 훈련/검증 범위에 넣기 전에는 기본 선공 정책을 명시한다. 이후 덱별 양 좌석의 동일 조건 비교로 예외를 학습한다.
3. 위력 감소를 포함한 실제 엔진 해결 결과로 제거·점거 차단을 계산한다. draw 존재와 대상 선택의 우열을 분리하고, 같은 소모·드로우에 추가 이득이 있는 대상을 비교한다. 상대 대응 가능성은 별도로 평가한다.
4. 신고 수신→재생 검증→장면 추출→교정/회귀검사의 처리 현황을 추적한다. 검증을 통과하지 못한 로그를 조용히 미사용으로 남기지 않는다.
5. 국소적으로 증명되는 실수의 회귀 검증과 제한적인 정책 학습을, 전체 모델 승급에 필요한 통계 검정과 분리한다. 최종 승패만 같다는 이유로 명백한 카드/자원 낭비를 좋은 행동으로 취급하지 않는다.
