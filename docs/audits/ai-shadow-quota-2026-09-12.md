# Shadow 추가 수집 목표 수정

2026-09-12, `data/ai/retrain-run-c-20260905-051719`에 적용했습니다.

## 원인

Shadow 완료 판정은 `training.acceptedGames`를 사용했지만, 추가 수집 목표는
전체 `audit.acceptedGames`에서 계산했습니다. 보정 자료 215경기가 포함되어,
학습용 1,354경기에서 32경기를 추가하려던 목표가 1,601경기로 늘어났습니다.
올바른 목표는 1,386경기입니다.

또한 작은 보충 묶음의 설정이 Shadow 경로에 전달되지 않았습니다.
해당 코드는 사용하지 않는 기존 진단 경로에 놓여 있었고, 그 경로에서는
정의되지 않은 `shadowRequirement`를 참조했습니다.

## 변경

- 목표 확장 함수에 학습 파티션의 감사 결과를 명시적으로 전달합니다.
  누락되거나 잘못된 경기 수는 전체 경기 수로 대체하지 않고 오류로 처리합니다.
- 수집 계약에 `role: training`과 버전 3을 기록합니다.
- 작업 전달 시 Shadow 보충 수집량을 `rollingWindowGames`에 반영합니다.
  현재 요청은 32경기이며, 보호된 검증 파티션의 설정에는 적용하지 않습니다.
- 잘못 놓인 기존 진단 경로의 코드를 제거했습니다.

## 검증

- 집중 테스트 12개와 관련 기존 회귀 테스트 3개 통과.
- 전체 1,569경기 중 학습용 1,354경기, 보정용 215경기를 재현해 목표가
  1,386경기가 되는지 확인했습니다. 1,385경기에서는 통과하지 않습니다.
- 기존 1,500 비교쌍 조건은 그대로 유지되며, 쌍이 부족하면 통과하지 않습니다.
- 실제 직렬화와 복원 과정에서 32경기 설정이 유지되는지 확인했습니다.
- 현재 실행에 필요한 호환 처리는 마지막 감사 결과의 전체 경기 수가 호출 값과
  일치하는지 검사한 뒤 그 감사 결과의 학습 경기 수만 전달합니다.
  보정 경기 수를 고정 상수로 빼는 처리를 후속 수집에 사용하지 않습니다.

## 현재 실행 적용

부모 프로세스 30148과 평가 프로세스 26120의 현재 목표를 함께 수정했습니다.
부모가 다음 Shadow 점검에 넘기는 요구사항도 같은 객체에서 수정했습니다.
재시작용 작업 요청 파일에도 반영했고, 엔진 지문과 자료 키는 유지했습니다.

수정 시점에 학습용 1,484경기를 확보해 올바른 목표를 이미 충족했습니다.
실행 중 워커를 종료하지 않고 현재 묶음의 신규 배정을 닫았습니다.
아직 시작하지 않은 45개 작업은 배정하지 않으며, 진행 중인 16경기가 저장되면
기존 단계 완료 경로를 통해 Shadow 자료 재점검으로 돌아갑니다.
이는 Shadow 성능 통과나 모델 학습 완료를 의미하지 않습니다.

Normal 우선순위, 최대 16개 워커, 게임 시간 제한 없음은 유지합니다.
원래 자료와 모델을 다시 계산하거나 변환하지 않았습니다.

변경 전 파일, 검증 결과 및 실제 적용 기록:
`.tmp-shadow-quota-20260912/`의 `correction.json`, `runtime-adapter-proof.json`,
`live-applied.json`, `final-verification.json`.
기존 부모의 중단 없는 실행을 위해 적용한 호환 함수는 해당 프로세스에서만
사용합니다. 재시작 시에는 수정된 파일의 학습 파티션 전달 경로가 적용됩니다.
