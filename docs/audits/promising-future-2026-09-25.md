# Promising Future 규칙·구현 검증

검증일: 2026-09-25. 현재 작업 디렉터리의 수정 사항을 포함한 엔진을 검사했습니다. 범위는 1대1의 수동 선택·지불·체인 우선권, 자동 선언, 저장 후 복원 경로입니다.

**수정 결과: 감사에서 확인한 오류 6개를 모두 수정했습니다.** 최초 재현 검사 11개는 5개 통과·6개 실패였으며, 수정 후에는 추가 검사 4개를 포함한 정규 PF 회귀 검사 15개가 모두 통과합니다. 수정은 카드 이름별 예외 없이 공용 확정·트리거·선택 처리에 적용했습니다.

## PF의 처리 순서

아래는 A가 자신의 턴에 PF를 사용하고 B가 상대인 일반적인 1대1 상황입니다.

1. 각자 메인 덱 위에서 최대 5장을 봅니다. 본 카드 전부를 상대에게 공개하는 효과는 아닙니다.
2. A부터 한 장을 선택해 추방하고 나머지를 재활용합니다. 추방한 카드는 공개되므로 B는 A의 선택을 알고 자기 카드를 고릅니다.
3. 선택이 끝나면 **B 카드 → A 카드** 순서로 체인에 미확정 항목을 올립니다. PF 해결 도중 각 카드를 곧바로 해결하지 않습니다.
4. PF의 해결을 완료합니다. PF를 플레이한 것에 대한 Lux 등의 트리거가 이때 발생합니다.
5. 가장 오래된 미확정 항목부터 **하나씩** 대상·선택·비용을 확정합니다. 유닛·장비는 자기 확정 직후 즉시 등장하고, 등장 효과는 체인 위에 별도 미확정 항목으로 추가됩니다. 뒤쪽 카드보다 먼저 그 등장 효과를 확정하면 안 됩니다.
6. 미확정 항목 처리가 끝나야 일반 반응 기회가 열립니다. 남아 있는 주문·능력은 위에서부터 하나씩 해결됩니다.

PF는 기본 에너지 비용을 무시하지만 파워 및 별도 추가 비용까지 없애지는 않습니다. 남은 비용을 지불하지 못하거나 허용되는 자원 지불을 거절하면 선택 카드는 추방 상태에 남습니다. 비용을 줄여도 카드에 인쇄된 비용을 참조하는 Lux 같은 조건이 0으로 바뀌는 것은 아닙니다.

순서 판정의 핵심 근거는 Core Rules 354.3(PF의 해결을 우선 완료), 337.1–337.3(오래된 항목부터 확정, 유닛·장비는 즉시 해결), 383.4.a.2(등장 효과의 별도 항목화), 355.9.a(대상의 영역), 359.3.e.11(가능한 지시는 부분적으로 수행)입니다.

모든 사례에서 필요한 비용은 지불하고, 선택 능력은 사용하며, 별도의 반응은 하지 않는 조건입니다.

| 검사 | 올바른 결과 | 수정 전 결과 | 수정 후 |
| --- | --- | --- | --- |
| 위 5장, 선택·공개·재활용 | A 선택 후 B 선택, 남은 4장은 덱 아래로 재활용 | 일치했습니다 | 통과 |
| 카드 체인 배치와 비용 | B→A로 미확정 배치, B부터 파워 지불, 기본 에너지 면제 | 일치했습니다 | 통과 |
| 파워 부족 | 선택 카드가 추방 상태에 남음 | 일치했습니다 | 통과 |
| 양쪽 파워 지불 거절 | 각각 거절할 수 있고 추방 상태 유지 | 일치했습니다 | 통과 |

| A Aurora / B Disarming Rake | Rake 등장 효과는 Aurora 등장 후 확정되어 파괴 가능 | Aurora 등장 전에 대상이 없다고 효과를 버립니다 | **통과** |

| A Lux+Progress Day / B Sabotage | PF의 Lux 1장 + Progress Day 4장 + 그 Lux 1장, 합계 6장 드로우 후 Sabotage | PF의 Lux 트리거가 누락되어 5장만 드로우합니다 | **통과** |

두 Star-Crossed 사례의 초기 전장은 A의 A1, B의 B1/B2입니다. B는 B1/A1을 먼저 선언하고, A는 A1/B2를 나중에 선언합니다. Elder Dragon 사례는 다른 유닛 없이 자신의 등장 효과로 상대 Dragon을 선택했습니다.

## 수정 내용

- `src/engine.mjs`의 `finalizeOutstandingChainItems`가 가장 오래된 미확정 항목 하나의 선언·지불·확정·즉시 등장을 완료하고 다음 항목으로 진행합니다. 처리 중 재진입하거나 자동 패스로 다음 단계가 앞서 나가는 것을 막았습니다.
- 뒤에 추가된 등장 효과는 체인에 보존하되, 오래된 항목이 확정될 때까지 대상 선언과 지불을 보류합니다. 재개 정보는 체인이 소유합니다. 지불 도중 사망 처리를 마쳐야 하는 기존 continuation은 유지합니다.
- 자동 선언 경로에서도 이미 열린 체인에 등장 효과를 추가합니다. JSON 저장 후 복원할 때는 체인 항목의 트리거를 다시 연결해 중복 생성이나 대기 상태 정지를 방지합니다. `server/snapshots.mjs`는 이 내부 재개 정보를 플레이어 스냅샷에서 제외합니다.
- 선택 가능한 대상이 0개였던 선택적 선언을 명시적인 건너뛰기로 보존합니다. 해결할 때 새 대상을 얻지 못합니다.
- `finishSpell`은 마지막 선택자가 아니라 주문의 컨트롤러를 기준으로 플레이 트리거를 발생시킵니다. A의 Lux 누락 및 B의 Lux 오발동을 함께 수정했습니다.
- Star-Crossed는 이미 선언한 대상이 있을 때 적 대상 부재만으로 종료하지 않고, 남은 적법한 아군 대상 지시를 수행합니다.
- `scripts/run-regression-mutants.mjs`의 확정 처리 변이 지점을 새 공용 처리 경로에 맞추고, 자동 선언 시 체인을 벗어나는 오류를 PF 회귀 검사로 검증하도록 연결했습니다.

## 재현 방법과 검사 범위

```powershell
node --test tests/promising-future.test.mjs
npm run check:no-ai
```

정규 PF 회귀 검사 15개가 모두 통과합니다. 최초 감사 파일 `docs/audits/promising-future-2026-09-25.test.mjs`도 정규 검사 파일을 불러오므로 기존 재현 명령을 그대로 사용할 수 있습니다. `promising-future-2026-09-25.results.txt`는 수정 전 실패 기록입니다.

추가한 4개 검사는 상대 Lux의 오발동 방지, Rake와 두 Dragon의 자동 선언 처리, 대기 중 저장·복원 및 플레이어 스냅샷 처리입니다. 기존 재현 검사는 실제 PF를 손에서 플레이한 후 공개 엔진 API로 선택, 지불, 패스를 수행합니다. 대상 카드의 효과·비용은 변경하지 않았습니다. 충분한 룬과 고정 덱을 준비하고, 자동 패스가 관찰 시점을 지나치지 않도록 양쪽 손에 효과 없는 시험용 Reaction을 두되 실제로 사용하지 않았습니다.

이 결과는 모든 카드 조합이나 2v2/FFA를 전수 검증했다는 의미는 아닙니다. 로컬 코드의 수정과 검증이며 배포는 수행하지 않았습니다.

## 추가 검증: Whirlwind와 내셔 남작

Whirlwind로 상대 내셔 남작을 선택해 손으로 돌릴 수 있어야 합니다. 정확한 근거는 선택 시점만이 아니라 **각 플레이어가 효과 해결 중 선택하는 지시는 대상 지정에서 제외된다**는 Core Rules 355.10.e입니다. 내셔 남작의 선택 불가는 대상 지정에 적용되므로 이 반환을 막지 않습니다. [공식 Origins FAQ의 Targeting 부록](https://playriftbound.com/en-us/news/rules-and-releases/riftbound-origins-faq/)도 여러 플레이어가 선택하는 지시의 예외를 설명합니다.

기존 구현은 Whirlwind의 선택 시점은 맞았지만, 각 플레이어가 자기 유닛만 고를 수 있도록 범위를 잘못 제한했습니다. 따라서 상대 내셔 남작을 고를 수 없었습니다. 공용 `eachPlayerReturnUnitToHand` resolver에서 전체 유닛을 허용하고, 비대상 선택으로 등록해 Deflect 비용과 대상 지정 전용 반환 대체 효과를 적용하지 않도록 수정했습니다. 내셔 남작의 카드 이름을 검사하는 예외는 추가하지 않았습니다.

`tests/whirlwind.test.mjs`의 신규 검사 4개가 모두 통과합니다.

- 기지에 있는 상대 내셔 남작을 양쪽 플레이어가 순서대로 반환합니다.
- 전장에 있는 상대 내셔 남작도 반환합니다.
- 상대가 반환을 거절해도 자신은 상대 유닛을 반환할 수 있으며, Deflect 비용을 지불하지 않습니다.
- Empowered Gangplank, Naval의 대상 지정에 따른 반환 대체 효과를 발동하지 않습니다.

실제 카드 비용을 지불하고 체인에 대한 양쪽 패스를 거친 후 선택하는 경로로 검사했습니다. 수정 전에는 신규 검사 4개 모두 실패했습니다.
