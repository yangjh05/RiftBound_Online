# 워커별 비교 정밀도 전달 누락 수정

## 원인과 영향

평가 수집기는 일부 게임의 `teacherLeafAuditSimulations`를 1024로,
자연 분포 게임의 `teacherLeafAuditPairBudget`를 1로 지정했지만,
자식 프로세스의 작업별 설정 허용 목록에는 두 필드가 없었다.
실제 계산은 기본 128회를 사용하면서 표본 계획에는 1024회가 남았다.
계획과 실행이 다른 비교는 기존 검증기가 거절하고,
별도로 유효한 상태 가치 자료는 유지했다.

2026-09-10 조사 시점에 수정 후 수집된 294게임 중
1024회로 배정된 67게임에서 유효한 행동 우열 비교는 0건이었다.
이 수치는 전체 게임이나 상태 가치 자료가 손실됐다는 뜻이 아니다.
기존 자료의 계획이나 반복 횟수를 사후에 바꿔 유효한 결과로 간주하지 않는다.

## 수정

- `scripts/ai-selfplay-task-options.mjs`에서 작업별 설정을 합친다.
  반복 횟수와 비교 개수도 전달하며 모델, 엔진, 시드, 저장 위치는
  초기화된 워커 설정을 유지한다.
- 실행 전 반복 횟수의 정수 범위와 표본 계획 일치를 확인한다.
  누락된 1024회 설정을 128회로 조용히 실행하지 않는다.
- 워커가 실제 적용한 설정을 부모에게 알리고,
  진행 정보와 저장 요약의 `appliedAuditSettings`에 기록한다.
  관리자가 요청한 `taskContext`와 구분해 확인할 수 있다.
- 긴 작업 목록의 자연 분포/집중 비교 작업을 교대로 배치한다.
  기존 비율과 각 집중 구간의 개수는 유지한다.
- 워커 증감 회귀 검사는 모델 초기화 시간에 의존하던 짧은 시간창 대신,
  실제 두 워커가 작업하는 것을 확인한 뒤 메모리 부족을 재현한다.

## 검증과 전환

- 실제 자식 프로세스에서 작업별 1024회/128회 및 비교 개수 1/2 전달,
  워커 확인 응답, 저장 요약을 검사한다.
- 긴 작업 목록의 첫 16개에 자연 분포 작업 8개가 포함되는지 검사한다.
- 격리된 게임 상태에서 실제 엔진으로 1024회 최종 비교를 실행하고,
  압축 저장 후 다시 읽어 비교 유효성과 실제 반복 수를 검사한다.
  이 검사 자료는 학습 데이터에 넣지 않는다.
- AI 회귀 검사와 재개/워커 진행 검사도 함께 실행한다.
- 현재 대국 저장이 끝나는 경계에서 재시작한다. 학습 자료를 이전하거나
  엔진 지문을 바꾸지 않는다. 워커 최대 16개와 작업 시간 제한 없음은 유지한다.
- 전환 기록: 학습 디렉터리의 `worker-precision-handoff.json`.
  실운영에서 새로 저장된 1024회 비교까지 검증한 뒤 `verified`로 기록한다.

통계 판정 기준은 변경하지 않았다. 정확한 1024회 계산이 연결되는 것과
최종 Shadow 성능 검증을 통과하는 것은 서로 다른 검증이다.

### 이번 실행 결과

- 회귀 검사 283개 중 최초 282개 통과. 시간창에 의존한 워커 증감 검사
  1개는 위의 재현 방식으로 수정한 뒤 단독 재검사에 통과했다.
- 실제 워커의 확인 응답과 저장 요약에서 1024회/128회 전환 및
  비교 개수 1/2 적용을 확인했다.
- 격리 검사에서 최종 두 분기 합계 2048회 계산,
  1024개 표본 쌍, 유효한 비교 1건을 압축 저장 후 다시 확인했다.
- 엔진 지문, PPO 자료 키, 평가 자료 키가 변경되지 않음을 확인했다.
- 실운영 전환과 실운영 1024회 결과 확인은 위의 전환 기록에서
  `waiting-for-current-games` → `verified`로 구분한다.
