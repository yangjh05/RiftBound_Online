# 실전 행동 검증의 워커 병목 수정

169회차의 실전 로그 교정 검증이 68분 26초 동안 다음 학습 회차를 막았습니다. 기존 코드는 사례를 하나씩 처리하고 해당 풀을 최대 4워커로 제한했습니다. 일반 32경기 수집·학습은 직전 평균 6분 30초, 최근 6분 54초였으므로 주된 지연은 이 별도 검증 단계였습니다.

## 수정

- 서로 독립인 최대 네 사례의 작업을 하나의 공용 seed 작업 큐에 동시에 넣습니다. 한 사례가 느려도 다른 사례가 완료되는 즉시 다음 사례를 시작합니다. 사례별 selection 32쌍 → 통과 시 final 128쌍의 순서는 유지합니다.
- 해당 풀이 현재 총 워커 예산에 따라 커지도록 4워커 상한을 제거했습니다. 전체 16개 중 컨트롤러 1개·평가 1개를 제외하면 최대 14개를 사용할 수 있습니다.
- 실전 교정 동안 배경 검증은 새 작업 배정을 멈추고 진행 중 seed 작업을 저장한 뒤 워커를 반환합니다. 실제로 종료된 워커 수만큼만 실전 교정 풀의 한도를 늘립니다. 끝나면 배경 검증의 대기 작업을 이어갑니다. 풀 생성 중인 워커도 보수적으로 계산합니다.
- 계획 순서대로 결과를 저장하므로 완료 순서의 차이가 결과 순서, 표본 선택, 학습 데이터 순서를 바꾸지 않습니다. 중단 시 진행 중 seed 작업은 저장하고, 재개 시 동일한 task ID·시드·파일 검증을 통해 재사용합니다.
- 저장된 작업 파일의 비동기 검사 중 풀이 닫히면, 종료된 워커 큐에 새 작업을 넣어 대기가 끝나지 않는 경합도 재현했습니다. 검사 후 종료 상태를 다시 확인하고 중단 사유를 전달하도록 수정했으며, 실패 재현 테스트가 수정 후 통과했습니다.
- 통계 기준, 시드, 모델, 검증할 사례 목록, 최종 검증 가족 크기, 현재 모델 일치 검사, 교정 채택 기준을 변경하지 않습니다.

현재 모델에 종속된 교정이므로 **검증 도중 모델 학습을 먼저 진행시키고 나중에 옛 결과를 덮어쓰는 방식은 적용하지 않았습니다.** 최종 검증 결과가 나올 때까지 기다리는 경계는 남습니다. 이번 수정은 이 경계 안의 순차 대기와 4워커 제한을 제거합니다.

## 검증

- 관련 테스트 27개 통과. 실제 별도 프로세스로 배경 6워커와 실전 교정 8워커가 총 한도를 지키고, 배경 작업 저장 후 실전 교정 14워커까지 확대되며, 종료 후 배경 작업을 재개하는 경로를 검사했습니다.
- 느린 첫 사례, 뒤섞인 완료 순서, 1차/최종 검증 순서, 중단, 오류 전파, 정책 일치·회귀 방지 검사를 포함합니다.
- 기존 169회차의 32개 사례·256개 저장 작업을 복사본에서 새 스케줄러로 다시 읽었습니다. 모든 판정과 교정 근거가 이전 결과와 정확히 일치했고, 원본과 복사본 256개 파일의 SHA-256도 그대로였습니다. 이 검사는 결과 보존/재개 검사이며 새로운 계산의 속도 측정은 아닙니다.
- 최종 고정 실행본은 `.tmp-ai-audit-throughput-final-20260927/runtime`입니다. 기존 720개 파일 중 실행 순서와 중단 처리 관련 3파일만 수정하고 스케줄러 도우미 하나를 추가했습니다. 전체 721개 파일의 해시를 검사했고, 학습 엔진의 raw/canonical 지문은 이전 실행본과 동일합니다.
- 09:24 KST에 189회차·1396세대 체크포인트에서 재개했습니다. 09:25:33 확인 시 새 190회차 경기 파일이 0개에서 9개로 증가했고, 대시보드 HTTP 200·실행 중·오류 없음·Normal 우선순위를 확인했습니다. 별도 승급평가 74는 같은 프로세스와 고정 요청을 유지한 채 278경기에서 281경기로 증가했습니다. 재개 전 모델, 설정·프로토콜 4개, 기존 평가 경기 278개의 해시가 보존됐습니다.

다음 정기 실전 교정은 201회차입니다. 실제 새 검증의 소요 시간은 이때 측정해야 합니다. 워커 수 증가만으로 실행 시간이 정확히 비례해 줄어든다고 주장하지 않습니다. 최종 실행본, 사전 검사, 기존 자료 보존 및 재개 확인 결과는 `.tmp-ai-audit-throughput-final-20260927`에 저장합니다.
