# 멀리건 간섭과 학습 갱신 정체 보완 검증

2026년 10월 2일, 일반 플레이를 학습할 때 기존 멀리건 정답을 잊어 PPO 갱신이 반복해서 취소되는 경로를 보완했습니다. 교정 사례의 정답 기준과 검증 기준은 유지했습니다. 과거 실패 회차 재현에서 실제 정책 갱신을 확인했으며, 이것이 승률 향상을 증명하는 것은 아닙니다.

10월 2일 16시 6분에는 검증을 마치고 91차 승급평가의 자연 종료를 기다렸습니다. 실제 교체는 같은 날 20시 3분에 이루어졌고 296회차부터 새 프로토콜로 학습했습니다. 10월 4일 후속 확인에서 실행본 759개 파일, 기존 자료 869개 파일, 실제 체크포인트의 프로토콜 해시 및 대시보드 HTTP 200을 검증했습니다. 원래 감독 프로세스가 실행 명령 반환을 기다려 완료 기록을 남기지 못한 상태여서, 독립 검증 후 유휴 감독만 종료하고 `migration-status.json`을 완료 상태로 정리했습니다. 학습기와 현재 평가기의 PID 및 시작 시각은 유지됐습니다.

## 확인한 문제와 변경

### 같은 교정 사례만 반복하는 복습 순서

기존 복습 위치는 epoch와 batch만으로 정했습니다. 갱신이 거부되어 매 주기 첫 epoch로 돌아오면 같은 사례를 다시 봅니다. 재현한 회차는 일반 PPO 배치가 4개이고 유형당 배치별 사례가 2개여서, 64개가 있는 유형에서는 앞의 8개만 일반 PPO 복습에 참여했습니다. 나머지 사례가 모든 학습에서 제외된 것은 아닙니다. 전체 사례를 쓰는 별도 경사 투영과 유지 검사에는 참여했습니다.

새 경로는 학습 주기 번호도 복습 위치에 반영합니다. 유형별 사례 수와 서로소인 간격을 사용해 17개, 34개처럼 특정 간격과 나누어떨어지는 은행도 빠짐없이 순환합니다. 주기와 epoch, batch가 같으면 재시작 후에도 같은 사례를 선택합니다. 사례 수와 복습 계수는 늘리지 않았습니다.

### 일반 플레이와 멀리건의 공유 가중치 간섭

이전 분석에서 검증 멀리건 한 장면의 정답과 잘못된 대안의 점수 차이는 약 0.000063이었습니다. 유형 평균 손실은 개선되어도 이 장면의 선택이 뒤집혀 전체 갱신이 거부됐습니다. 실제 대안은 교사 계산상 동등한 정답이 아니었습니다.

새 경로는 먼저 전체 정책 갱신을 시도합니다. 실패하면 멀리건 행동에서 항상 0인 행동 종류 입력 행만 갱신하는 별도 경로를 사용합니다. 변경 대상은 `actionProjection`과 `actionBias`의 커널 행 6부터 20, 67입니다. GRU, 상태 투영, 실제 행동 점수에 더해지는 Q, 모든 절편, 카드·해시·상황 입력 행은 그대로 둡니다. 같은 상태·행동·기억 입력의 멀리건 점수가 정확하게 보존되는 것을 검사했습니다.

이 제한 경로도 실제 PPO 제안과 검증된 학습용 교정 경사에서 방향을 계산합니다. 검증용 정답을 경사 계산에 쓰지 않습니다. 일반 플레이의 모든 능력을 한 번에 학습하는 구조는 아니며, 전체 정책 갱신은 이후 주기에도 계속 시도합니다. 제한 갱신도 실패하면 기존의 제한된 복원 경로를 시도하고, 끝까지 검증에 실패하면 모델·Adam·난수를 모두 되돌립니다.

### 불필요한 복원 시도와 투영 크기

저렴한 제한 갱신을 기존의 추가 복원 시도보다 먼저 확인합니다. 제한 갱신이 성공하면 뒤의 복원 검사를 실행하지 않습니다. 단순히 실패한 학습을 성공으로 표시하는 변경은 아닙니다.

경사 제약을 만족시키는 과정에서 투영된 갱신이 원래 제안보다 과도하게 커질 수 있으므로, 새 경로의 전체 경사 투영과 행동 행 투영에는 원래 제안 노름의 2배 상한을 추가했습니다. 기존 프로토콜의 기본 동작은 바꾸지 않았고, 새 프로토콜에서만 적용합니다.

### 평가 프로세스의 수명

기존 평가 실행은 학습기의 IPC와 출력 스트림을 상속했습니다. 이전 교체 시 평가 프로세스가 사라진 사실은 확인됐지만, 종료 원인 자체는 확정되지 않았습니다.

새로 실행하는 평가기는 별도 프로세스 그룹과 파일 출력을 사용합니다. 부모 프로세스가 종료된 뒤에도 평가기가 진행 및 완료 파일을 저장하는 테스트를 통과했습니다. 이미 실행 중인 91차 평가기는 이 변경의 보호를 소급해서 받지 않으므로, 이번 교체에서는 해당 평가의 자연 종료를 기다립니다.

## 적용과 보호 범위

새 프로토콜은 `prospective-phase-preserving-policy-v1`이며 기존 효율화 프로토콜의 해시에 결합됩니다. 적용 경계, 프로토콜 해시를 상태와 epoch 체크포인트에 기록하고, 재개할 때 바뀌었으면 거부합니다. 과거 프로토콜이나 과거 epoch를 새 의미로 덮어쓰지 않습니다.

교체 감독 프로세스는 다음 평가의 mutex만 예약해 추가 평가가 이전 학습기에 붙어 시작되는 것을 막습니다. 91차 평가의 요청·시드·모델·실행 프로세스·기존 경기 파일에는 손대지 않습니다. 91차 완료 후 정상 저장을 요청하고, 체크포인트와 기존 파일 지문을 보존한 다음 새 학습기를 시작합니다. 워커 상한 16개와 저장된 우선순위, 기존 run, 빅토르 학습, 대시보드를 유지합니다.

감독 프로세스는 첫 학습 주기 완료, 새 프로토콜 해시, 실제 정책 체크포인트 기록, 기존 파일 지문, 대시보드 HTTP 200까지 확인한 뒤에만 완료를 기록합니다. 검증이나 실행이 실패하면 오류를 남기며 성공으로 기록하지 않습니다.

재현·검사 자료는 `.tmp-ai-phase-learning-20261002/checks.json`, `trial-282-final.json`, `trial-277-release.json`, `tests-root.log`, `tests-pinned.log`에 있습니다. 이번 작업은 학습 갱신과 재개 경로에 대한 집중 감사이며, 모든 게임 전략과 카드 조합에 결함이 없다는 보장은 아닙니다.
