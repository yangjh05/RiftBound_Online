# 준비 상태 진입 주문의 행동 순서 보완

정면승부는 이후에 내는 유닛을 준비 상태로 진입시키며 카드 한 장을 뽑습니다. 이미 낸 유닛을 준비시키는 효과는 아닙니다. 카드와 엔진 효과는 변경하지 않았습니다.

## 판단 기준

- 카드 이름 대신 `spell:unitsEnterReadyThisTurn` 효과를 기준으로 적용합니다.
- 같은 주문과 유닛을 실제 비용까지 지불하여 `주문 → 유닛`과 `유닛 → 주문` 두 순서로 실행합니다. 준비 여부가 실제로 달라지는 경우에만 순서 비교를 적용합니다.
- 유닛 선행으로 발동 효과가 생겼다는 사실만으로 예외를 허용하지 않습니다. 공개정보로 확인한 순효과가 준비 상태의 후속 이득보다 커야 합니다. 작거나 같으면 준비 상태를 확보하는 순서를 우선합니다.
- 두 순서의 후속 이동·전투·득점 또는 능력 사용과 턴 종료 결과를 비교합니다. 사용하지 못한 일시적 위력은 엔진의 턴 종료 처리에서 만료되므로 남는 이득으로 평가하지 않습니다.
- 주문 비용을 쓰지 않고 유닛만 내는 선택도 비교합니다. 준비 상태의 이득이 추가 지출을 보상하지 못하면 유닛만 내는 선택을 유지합니다. 주문이 손에 있다는 이유로 무조건 사용하도록 만들지 않습니다.
- 유닛을 이어서 낼 수 없는 드로우 용도는 금지하지 않습니다. 한쪽 순서의 비용을 지불할 수 없거나 결과를 끝까지 처리할 수 없는 경우에도 행동을 임의로 금지하지 않습니다.

각 중간 순서의 처리에는 최대 64개 상태, 후속 행동 비교에는 행동당 최대 128개 상태를 사용합니다. 유닛 후보는 최대 6개입니다. 후속 행동 후보가 16개를 넘으면 해당 비교를 적용하지 않습니다. 후속 전략 행동 한 번까지 비교하며 여러 행동을 연결하는 모든 조합을 검색하지 않습니다. 상대의 선택 가능한 반응은 없다고 가정하며, 상대의 필수 선택은 기존 공개 전술 미리보기의 지원 범위에서만 처리합니다. 숨겨진 손패나 앞으로 뽑을 카드의 실제 정체는 가립니다.

순효과 평가는 기존 공개 전술 평가 함수를 사용합니다. 승패, 점수, 전장 지배, 남은 카드·유닛·자원 등을 가중 평가한 기본 선호입니다. 완전 탐색의 최적성 증명이나 상대 반응에 대한 승률 보증이 아닙니다. 복잡한 효과 때문에 비교가 미완료되면 정책에 선택을 남깁니다.

## 모델과 학습

양쪽 플레이어의 `unitsEnterReadyThisTurn`, `nextUnitEnterReady`를 관찰 및 상태 입력에 추가했습니다. 기존 6,018개 입력 뒤에 네 값을 덧붙여 6,022개가 됩니다. 기존 가중치는 보존하고 추가 입력에 연결되는 가중치만 0으로 초기화합니다. 행동 입력 480개는 그대로입니다.

전술 예시 생성은 `준비 진입 주문 → 유닛 → 즉시 이동`을 탐색하고 이어지는 선택들을 학습 예시로 기록합니다. 실제 대전의 정책과 자가 대전 모두 동일한 행동 순서 필터를 사용합니다. 기존 모델의 새 입력 가중치는 추가 학습이 필요하며, 예시 선택 일치율 향상은 사람 상대 실력 향상을 증명하지 않습니다.

이전 `adaptive-policy-q-human-tactics-20260915` 실행은 2회차를 저장하고 종료했습니다. 177세대 체크포인트를 바이트 그대로 새 `adaptive-policy-q-ready-entry-20260915` 실행으로 이전했습니다. 기존 경기의 행동 확률이나 평가 결과를 새 코드로 재분류하지 않았습니다. 직전 실행 기록 287개 파일 및 이전 보존 검증을 유지합니다.

전술 예시 학습용 결정 328개, 별도 검증용 결정 143개를 확보했습니다. 검증 정책 손실은 1.1261에서 1.0044로 감소했고 선택 일치율은 59.4%로 같았습니다. 이후 1회차 자가 대전 수집으로 진행했습니다. 사람 대전 목록에는 이 전술 학습을 마친 177세대를 시험 모델로 추가했으며, 기존 챔피언 승급을 의미하지 않습니다. 138·162·175세대 파일은 유지했고 177세대의 실제 브라우저 로딩도 별도로 확인했습니다.
