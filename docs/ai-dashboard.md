# AI 학습 대시보드

```powershell
npm run ai:dashboard
```

이 PC에서 http://127.0.0.1:4180/ 을 여시면 됩니다. 게임 서버와 독립적으로 실행하므로 게임이나 학습을 재시작할 필요가 없습니다. 대시보드 서버를 종료해도 학습은 계속됩니다.

## 표시하는 기록

- `data/ai` 아래의 adaptive 학습 실행을 자동으로 발견합니다. 실제 프로젝트 학습 프로세스와 일치하는 실행을 우선하며, 실행 중인 학습이 없으면 마지막 저장 기록임을 표시합니다.
- 현재 학습 목표 세대, 마지막 저장 세대, 챔피언 세대를 구분합니다. 진행률은 현재 단계(자가대전 수집 경기 또는 정책 학습 epoch)의 진행률입니다. 전체 학습은 연속 반복이므로 전체 완료율을 만들지 않습니다. 평가기 학습처럼 세부 진행 기록이 없는 단계는 ‘진행 중’으로 표시합니다.
- 평가의 저장된 경기만 집계합니다. 미완료·무효·인위적 판정 경기는 승률에서 제외합니다. 승률은 승리/유효 경기, 통계 판정의 승점률은 (승리+무승부×0.5)/유효 경기입니다.
- 현재 평가의 누적 승률, 덱별 후보 세대 승률, 정책 손실, 분당 수집 경기, 평가 이력과 최근 완료된 승급평가를 제공합니다. 덱 이름을 누르면 그래프에서 숨기거나 표시할 수 있습니다.
- 승급평가와 고정 기준 AI 평가는 별도 그래프입니다. 챔피언이 바뀌면 승급평가 상대도 바뀌므로 고정 상대 성장 측정과 동일하게 해석하지 않습니다. 고정 기준 평가의 통과는 승급이 아닙니다.
- 평가의 통계 구간은 학습기가 저장한 공식 판정 그대로입니다. 아직 판정에 포함되지 않은 최근 경기는 화면 승률에는 포함되므로 표본 수가 다를 수 있습니다. 평가 종료 이유와 ‘우위 미확인’을 구분합니다. 이력과 누적 수치는 선택된 학습 실행 범위입니다.
- 학습 기록은 읽기만 합니다. 가중치, 학습 조건, 학습 자료 및 승급 기준을 바꾸지 않습니다. 화면은 3초마다 갱신되며, 원본 기록은 단계별 저장 주기에 따라 갱신됩니다.
- 비정상 재부팅으로 진행 로그의 일부 줄이 손상되면 해당 줄을 건너뛰고 이후 정상 기록을 표시합니다. 누락된 줄 수를 화면에 알리며 원본 파일이나 평가 경기 결과는 수정하지 않습니다. 아직 줄바꿈이 기록되지 않은 마지막 줄은 다음 갱신까지 기다립니다.

## 덱 구성 탐색

`deck-search-protocol.json`이 있는 실행에는 오리진 덱 탐색 패널을 표시합니다. 카드 풀은 Origins·Proving Grounds이며 금지카드는 제외합니다.

- 203회차부터처럼 실제 전환 경계를 기준으로 완료 회차와 저장 경기를 집계하고 훈련·독립 검증 경기를 구분합니다. 현재 확정된 경기 배정과 기준·변형 덱 수, 합법성 검사 결과도 표시합니다.
- 기준 50%·소규모 변경 25%·넓은 탐색 25%는 시험 덱 배정 비율입니다. 상대는 기준 덱이므로 전체 좌석의 비율은 아닙니다. 정책 승급 평가는 전설별 대표 5개 합법 덱으로 따로 진행합니다.
- 전설 필터와 구성 보기로 후보별 카드·매수, 평균 비용, 오로라 채용 수, 상대별 비교 표본을 확인합니다. 한국어 명칭은 게임의 공용 번역 데이터를 사용합니다. 자동 보정한 출발점에는 성능 미검증 표시를 붙입니다.
- 탐색 점수는 학습기가 저장한 상대·좌석·선후공 균등 보정 성적을 0~100점으로 표시합니다. 독립 검증 경기와 동일 구성끼리의 경기는 후보 선택에서 제외합니다. 0경기인 덱은 중립 사전값 50점을 측정 성적으로 표시하지 않고 ‘비교 대기’로 표시합니다.
- 선택한 후보의 최근 40회차 점수와 오로라 채용·미채용 기준 덱의 점수, 비용 분포를 비교할 수 있습니다. 정책이 계속 바뀌는 탐색 통계이므로 실제 승률, 오로라의 인과 효과, 최강 덱 인증으로 해석하지 않습니다. 사이드보드 성적은 단판 학습의 평가 대상이 아닙니다.
- 회차 저장이 끝난 성적만 반영하고 저장 대기 상태를 구분합니다. 기존 평가 덱과 새 합법화 덱은 서로 다른 구성 ID로 유지하여 과거 승률을 합쳐 표시하지 않습니다. 탐색 패널은 가중치나 대전 궤적을 읽지 않고 계획·상태·소형 성적 파일을 사용합니다.

## 별도 덱 학습과 본학습 통합

`isolated-fixed-deck-pilot-v1` 실행은 본학습과 별도 패널에 표시합니다. 특정 본학습을 `--run-dir`로 지정해도 연결된 별도 학습을 함께 찾으며, 최근에 시작한 파일럿이 본학습 표시를 대신하지 않습니다.

- 빅토르 패널에는 현재 목표 세대와 저장 세대, 이번 회차 수집 진행률, 누적 수집·학습 완료 경기를 구분합니다. 최초 시험은 32경기씩 4회이며, `continuous-training-protocol.json`이 있으면 횟수 제한 없는 독립 연속 학습으로 표시합니다. 최초 128경기와 320경기 진단 완료를 전체 학습 완료로 표시하지 않습니다.
- 연속 학습은 프로토콜의 주기로 다음 평가를 표시합니다. 현재는 최초 4회차 이후 추가 16회차(512경기)마다 미러 64경기, 추가 64회차(2,048경기)마다 미러·교차 합계 320경기를 평가합니다. 첫 정기 미러는 20회차, 첫 정기 교차는 68회차입니다. 평가가 끝나면 학습을 이어가며 전체 종료시간은 없습니다.
- 최근 8회차의 수집 그래프만 읽고 누적 학습량은 검증된 저장 상태를 기준으로 계산합니다. 평가 중 아직 시작하지 않은 다음 회차를 현재 회차로 만들지 않습니다. 누적 수치에 현재 회차의 진행률을 혼동해 붙이지 않습니다.
- 교차 검증은 후보 모델이 빅토르를 잡은 경우와 상대 덱을 잡은 경우를 나눠 학습 전후 승률 막대로 표시합니다. 전후 각 16경기가 모두 모인 역할만 변화량을 표시합니다. 아직 경기가 없으면 0% 대신 대기로 표시합니다.
- 최근 평가의 회차·후보 세대·평가 형식·완료 여부를 별도로 표시합니다. 최근 평가가 미러만 진행했더라도 이전 교차 평가의 승률 비교는 해당 평가의 세대를 명시하고 유지합니다.
- 유한 시험은 미러 학습 → 독립 검증 → 결과 검토 → 본학습 점진 통합으로, 연속 모드는 수집·정책 학습·정기 평가 반복과 향후 통합 계획으로 표시합니다. 본학습 설정에서 해당 덱을 발견하면 설정 반영 상태로 바뀝니다.
- 실제 프로세스와 일치하는 파일럿 및 수집 워커 수, 현재 별도 예약 슬롯 수를 표시합니다. 우선순위 제어에는 파일럿 컨트롤러와 이후 생성되는 자식도 포함됩니다.
- 검증 종료 예상은 실제 검증 경기 저장 속도가 쌓인 뒤 계산합니다. 미러 수집 속도를 정책 학습이나 검증 전체에 대입하지 않습니다. 개별 평가 파일을 저장하는 도중의 불완전 JSON은 다음 갱신에서 재시도합니다.
- 현재 빅토르 덱의 카드·매수와 공개 게임으로 가는 링크를 제공합니다. 대시보드는 학습 설정, 예약 슬롯, 가중치, 승급 상태를 수정하지 않습니다.

## 예상 결과와 종료시간

- 현재 순차 평가의 완전한 8경기 묶음을 덱별로 재표본화해 80개 모의 경로를 계산합니다. 선후공 결과를 함께 유지하며, 실제 학습기의 통계 판정·회귀 검사·조기 종료·연장 규칙을 그대로 적용합니다. 덱별로 최소 5묶음이 쌓여야 예상 결과를 표시하고, 새 덱 순환이 완료될 때 추정을 갱신합니다.
- 표시되는 예상 승률은 모의 종료 결과의 중앙값이며 범위는 가운데 80%의 모의 경로입니다. ‘80개 중 몇 개 통과’는 관측된 경기 패턴을 바탕으로 한 모의 결과이며, 보정된 실제 승급 확률이나 확정 판정이 아닙니다. 화면의 예측은 학습과 승급 결정에 사용하지 않습니다.
- 평가 종료시간은 최근 최대 80개 경기 간격의 평균과 모의 종료 경기 수로 계산합니다. 예측 자료가 부족하면 기본 경기 수 기준으로 표시하며, 최대 경기 수까지 진행할 때의 시각도 표시합니다. 마지막 경기 저장시각을 기준으로 계산하므로 같은 기록을 새로 읽기만 해도 ETA가 뒤로 밀리지는 않습니다. 처리 속도 변화와 중단은 예상시각에 영향을 줍니다.
- 현재 세대의 완료시간은 최근 최대 8회 반복에서 현재 단계 시작 이후 저장 완료까지 걸린 시간의 중앙값으로 추정합니다. 최소 3회 기록이 필요하며 평균 소요시간을 넘기면 완료 대기로 표시합니다. 계속 반복하는 전체 학습에는 정해진 종료시각이 없습니다.
- 평가가 중단되거나 최근 경기 기록이 오래되면 시간 추정을 보류합니다. 이미 종료된 평가는 실제 완료 상태를 표시합니다.

## 우선순위

낮음 / 낮은 보통 / 보통 / 높은 보통 / 높음 중 선택합니다. Windows에서 해당 체크아웃의 학습 프로세스와 Node 자식 프로세스만 선택합니다. 게임 서버, 대시보드, 다른 프로젝트의 프로세스는 대상이 아닙니다. 설정은 `data/ai/process-priority.json`에 원자적으로 저장됩니다.

대시보드가 실행되는 동안 3초마다 새 프로세스에도 적용합니다. 학습 시작 명령과 adaptive 직접 실행에 연결된 `scripts/ai-training-priority.cjs`는 저장된 설정을 읽고, `NODE_OPTIONS`를 통해 이후 자식 프로세스 시작 시점에도 설정을 적용합니다. 이 초기화 경로를 사용하는 학습은 대시보드를 닫아도 설정을 유지합니다. 이전에 이미 시작된 프로세스는 대시보드의 감시 기능으로 적용합니다. 적용 실패나 운영체제 권한 문제는 화면에 별도로 표시하며 학습을 종료하지 않습니다.

제어 API는 로컬 주소로만 바인딩하고 Host·Origin·요청 토큰을 검사합니다. 게임의 공개 서버에 제어 기능을 추가하지 않습니다.

## 실행 옵션

```powershell
npm run ai:dashboard -- --port 4181
npm run ai:dashboard -- --run-dir "C:/path/to/adaptive-run"
npm run ai:dashboard -- --data-dir "C:/path/to/data/ai"
```

`--run-dir`은 자동 선택 대신 특정 실행을 표시합니다. 우선순위 제어 범위는 항상 이 프로젝트의 학습 프로세스입니다. Windows 이외의 환경에서도 기록을 읽을 수 있지만 프로세스 우선순위 제어는 비활성화됩니다.

## 학습 출발점 비교 대시보드 (2026-10-04)

기본 화면은 **진행 상황 / 공식 승급평가 / 덱·별도 학습 / 학습 기록**으로 나뉩니다. 각 화면은 키보드 방향키로 전환할 수 있으며, 모바일에서도 동일한 기록을 제공합니다.

- 진행 상황은 공식 챔피언, 마지막 저장 본학습 모델, 두 출발점 비교 실험, 전체 실행 프로세스를 구분합니다. 세대 번호는 분기마다 별개이며 번호 크기로 실력을 비교하지 않습니다.
- `learner-anchor-protocol.json`과 본학습 상태를 읽어 현재 기준점, 기준점 이후 완료 회차, 서로 다른 후보의 확정 열세 횟수, 실제 기준점 변경 이력을 표시합니다. 두 복귀 조건을 모두 충족한 경우에만 다음 새 회차의 복귀 대상으로 표시합니다. 비교 실험 완료를 본학습 반영으로 간주하지 않습니다.
- `paired-champion-current-learning-v1` 비교는 두 출발점의 회차별 저장 경기, 후보 저장, 반영·거부 학습 단계, 교정 사례 보존 검사를 보여줍니다. 수집 경기와 가중치 학습에 사용된 경기를 구분하며, 교정 사례의 훈련/검증 및 관측 이력 복원/기존 기억 비율도 표시합니다.
- 선별 평가와 새 시드의 확인 평가를 나누고, 평가 파일을 가중치 지문·상대·시드·설정에 결합해 읽습니다. 같은 세대 번호만으로 경기를 재사용하지 않습니다. 완성 파일과 중간 저장이 함께 있으면 완성 파일만 집계하고, 무효 경기는 승률에서 제외합니다. 변화를 확인하지 못해 생략된 평가는 승률 0%로 표시하지 않습니다.
- `league-evaluation-schedule.mjs`의 순수 일정 함수를 학습기와 대시보드에서 공유합니다. 화면에서 TensorFlow 모델을 실행하지 않습니다. 모델 파일은 필요한 메타데이터만 추려 파일 변경 시 캐시를 갱신하며, 경기 궤적은 진행률을 위해 압축 해제하지 않습니다.
