# 리프트바운드 한국어 카드 번역 단일 기준

이 문서는 이 프로젝트의 한국어 카드명, 카드 유형, 비용, 효과 문구와 키워드를
작성·검수할 때 사용하는 **유일한 번역 기준 문서**입니다. 오리진(`OGN`),
증명의 전장 스타터(`OGS`), 스피릿포지드(`SFD`), 언리쉬드(`UNL`)에 모두
적용합니다.

영어 원문의 규칙 의미와 한국어 실물 카드의 정식 문구가 충돌하지 않는 한,
대상, 수량, 비용, 시점, 선택 가능성, 처리 순서를 모두 보존합니다. 자연스럽게
보이도록 의미를 요약하거나 원문에 없는 동사를 보충하지 않습니다.

## 1. 기준의 우선순위와 불확실성

번역 근거는 다음 순서로 우선합니다.

1. 한국어판 실물 카드에서 직접 확인한 인쇄 문구
2. 사용자가 한국어판 실물 카드에서 정확히 전사했다고 명시한 문구
3. 공식 정오표·FAQ가 수정한 규칙 의미
4. 공식 영문 카드 문구를 이 문서에 따라 옮긴 프로젝트 번역

- 상위 근거가 하위 근거보다 우선합니다. 실물 문구가 일반 문형과 달라도 실물
  문구를 그대로 보존합니다.
- 사진이 흐리거나 문구가 가려졌거나 서로 다른 공식 자료가 충돌하면 임의로
  확정하지 않습니다. 기존 문구를 `비공식 번역` 상태로 유지하고 사용자에게
  확인합니다.
- 카드명과 효과 문구의 확정도는 별개일 수 있습니다. 카드명만 확인됐다면 효과
  문구까지 공식 한국어 문구라고 간주하지 않습니다.
- 커뮤니티 번역과 기계 번역은 공식 한국어 문구의 증거로 사용하지 않습니다.
- `Riftbound Origins FAQ`는 규칙 의미의 공식 근거입니다. 한국어 실물 문구를
  직접 보여 주는 자료가 아니므로, FAQ 기반 문장을 실물의 정확한 어순이라고
  주장하지 않습니다.

### 번역 데이터의 출처 표시

- 정식 한국어 문구 또는 프로젝트가 승인한 공식 규칙 교정에는
  `officialTextSource`로 근거를 남깁니다.
- 정식 한국어 문구가 확인되지 않은 효과는 `koText` 첫 줄에
  `비공식 번역`을 붙입니다.
- `공식 번역 미확인`이나 문장 끝의 `미확인`은 사용하지 않습니다.
- 한국어 실물에 효과 문장이 전혀 없으면 빈 문자열과
  `printedTextEmpty: true`를 함께 사용합니다.
- 불확실한 문구를 빈 문자열로 숨기지 않습니다. 빈 문자열은 실제로 인쇄 문구가
  없는 경우에만 사용합니다.

## 2. 번역 데이터 계약

각 카드 번역은 다음 필드를 완성합니다.

| 필드 | 용도 | 규칙 |
|---|---|---|
| `koName` | 카드명 | 확인된 고유명사를 사용하고 영문을 남기지 않습니다. |
| `koHeader` | 카드 상단 정보 | `[카드명], 에너지, 힘, 위력` 순서를 지킵니다. |
| `koTypeLine` | 유형·태그 | 카드 유형을 먼저 쓰고 챔피언·지역·종족 등을 쉼표로 구분합니다. |
| `koText` | 인쇄 효과 문구 | 확정 문구 또는 `비공식 번역\n`으로 시작하는 전체 문장을 넣습니다. |
| `officialTextSource` | 근거 | 실물, 사용자 전사, FAQ 등 실제 근거를 구체적으로 기록합니다. |
| `printedTextEmpty` | 무문장 카드 | 실물에 효과 문장이 없을 때만 `true`로 둡니다. |

- 등록된 모든 카드는 한국어 이름, 헤더, 유형 줄을 가져야 합니다.
- 영문 약어 `XP`, 고유 표기 `B.F.`를 제외한 번역되지 않은 영문 조각을 한국어
  메타데이터와 효과 문구에 남기지 않습니다.
- 임시 설명, 카드 번호만 바꾼 자리표시자, `카드 이미지의 인쇄 문구를 기준으로`
  같은 대체 문구를 사용하지 않습니다.
- 같은 카드의 일러스트 변형은 별도의 수집 번호를 유지하되 같은 인쇄 문구와
  확정도를 공유합니다.

### 실제 데이터 위치와 덮어쓰기 순서

- `OGN`·`OGS`: `src/cardKoTranslations.mjs`
- `SFD`: `src/cards/spiritforgedKoTranslations.mjs`
- `UNL`: `src/cards/unleashedKoTranslations.mjs`
- `VEN`: `src/cards/vendettaKoTranslations.mjs`
- 공통 키워드·유형·영역 이름: `src/i18n.mjs`

`SFD`, `UNL`, `VEN` 번역은 `src/cardKoTranslations.mjs`의 같은 번호 항목보다 나중에
병합됩니다. 따라서 실제 표시 문구를 수정할 때는 세트별 파일도 반드시 확인합니다.

| Recycle | 재활용 | `회수`와 구분합니다. |
| Reveal | 공개 | 카드를 확인만 하는 것과 공개하는 것을 구분합니다. |

| Mistarget | 대상 상실 | 선택 후 처리 시점에 대상이 부적합해진 상태를 뜻합니다. |
| Make new choices | 선택 다시하기 | 대상 또는 모드의 일부나 전부를 다시 선택하는 규칙 절차입니다. |
| Applied cost | 적용된 비용 | 카드 사용 외의 행동에 다른 효과가 적용한 비용입니다. |

### 영역과 힘 이름

| 영어 | 한국어 |
|---|---|
| `Body` | `신체` |
| `Calm` | `평정` |
| `Chaos` | `혼돈` |
| `Fury` | `격노` |
| `Mind` | `정신` |
| `Order` | `질서` |
| `Any` | `힘` 또는 카드 영역에 따른 `평정/신체 힘` 같은 범용 표기 |

`Calm`을 `인내`로 번역하지 않습니다. 힘 비용은 `1 평정 힘`, `2 격노 힘`처럼
수치, 영역, `힘` 순서로 씁니다.

### 카드 유형 이름

| 데이터 유형 | 한국어 |
|---|---|
| `legend` | `전설` |
| `battlefield` | `전장` |
| `unit` | `유닛` |
| `spell` | `주문` |
| `gear` | `도구` |
| `rune` | `룬` 또는 유형 줄의 `기본 룬` |

여러 유형을 지닌 카드는 가진 유형을 모두 표시합니다. Patched Porobot처럼 유닛과
도구 유형을 동시에 가진 카드는 유형 줄에 `유닛, 도구`로 쓰고, 문장에서는
`유닛이자 도구`로 씁니다. 공간이 제한된 상태 배지에서만 `유닛·도구`를 사용할 수
있습니다.

## 4. 키워드 사전과 확정도

`확정`은 한국어 실물 카드 또는 공식 한국어 근거로 확인한 표기입니다.
`잠정`은 현재 프로젝트에서 일관되게 사용하는 번역이지만, 정식 한국어판 근거가
추가되면 바뀔 수 있습니다. 잠정 표기를 정식 번역이라고 소개하지 않습니다.

| 영어 키워드 | 한국어 | 상태 |
|---|---|---|
| `Accelerate` | `가속` | 확정 |
| `Action` | `행동` | 확정 |
| `Assault` | `맹공` | 확정 |
| `Shield` | `보호막` | 확정 |
| `Deathknell` | `죽음의 종소리` | 확정 |
| `Deflect` | `굴절` | 확정 |
| `Ganking` | `개입` | 확정 |
| `Hidden` | `숨겨짐` | 확정 |
| `Legion` | `군단` | 확정 |
| `Reaction` | `반응` | 확정 |
| `Tank` | `탱커` | 확정 |
| `Temporary` | `일시적` | 확정 |
| `Vision` | `통찰` | 확정 |
| `Stun` | `기절` | 확정 |
| `Add` | `추가` | 확정 |
| `Mighty` | `강력` | 잠정 |
| `Empower` | `강화` | 확정 |
| `Empowered` | `강화됨` | 확정 |
| `Disempower` | `강화 해제` | 확정 |
| `Flow` | `흐름` | 잠정 |
| `Burn` | `소각` | 확정 |
| `Skip` | `건너뛰기` | 확정 |
| `Hunt` | `추적` | 잠정 |
| `Ambush` | `기습` | 잠정 |
| `Backline` | `후방` | 잠정 |
| `Buff` | `버프` | 잠정 |
| `Equip` | `장착` | 잠정 |

| `Predict` | `예측` | 잠정 |

| `Level` | `레벨` | 잠정 |

다음 과거 표기는 사용하지 않습니다.

- `[은신]` → `[숨겨짐]`
- `[방벽]` → `[보호막]`
- `[사냥]` → `[추적]`
- `[유언]` → `[죽음의 종소리]`
- `[예지]` → `[통찰]`
- `Ganking`의 다른 번역 → `[개입]`
- `Tank`의 다른 번역 → `[탱커]`
- `Mighty`의 서술식 번역 `강력한`, `강력합니다`, `[강력] 상태` → `[강력]`
- `Empower` → `[강화]`, `Empowered` → `[강화됨]`, `Disempower` → `강화 해제`
- `Flow` → `[흐름]`, `Burn` → `[소각]`, `Skip` → `건너뛰기`
- `[연소]`, `[태우기]`, `[덱 파괴]` → `[소각]`
- `번아웃`, `덱사` → `소진`

Vendetta 확정 용어는 공식 한국어 패치 노트와 공식 한국어 FAQ를 근거로 합니다.

- 패치 노트: <https://playriftbound.com/ko-kr/news/announcements/core-rules-vendetta-patch-notes/>
- FAQ: <https://playriftbound.com/ko-kr/news/rules-and-releases/vendetta-rules-faq-and-clarifications/>

### Vendetta 관련 명칭

| 영어 | 기준 한국어 | 상태 및 용도 |
|---|---|---|
| `Decree` | `칙령` | 잠정, 주문 태그 |
| `Tentacle` | `촉수` | 확정, 토큰명 |
| `Shadow Clone` | `그림자 분신` | 잠정, 토큰명 |
| `Empowered marker` | `강화됨 표식` | 잠정, 강화됨 상태 표시물 |

`Empowered marker`는 규칙상 강화됨 상태를 추적하는 표시물이므로 `강화 토큰`으로
번역하지 않습니다. 카드 효과가 생성하는 게임 오브젝트인 토큰과 상태 표시물을
구분합니다.

## 5. 지칭과 대상

### 플레이어와 카드의 구분

- `내가`는 플레이어 본인만 가리킵니다. 카드 자신을 `내가`, `나`, `자신`으로
  번역하지 않습니다.
- 플레이어의 소유·통제 영역은 `내`로 씁니다.
  - `내 폐기장`, `내 손`, `내 유닛`, `내가 통제하는 전장`
- 효과의 출처인 카드는 `이 카드`로 씁니다.
  - `이 카드를 사용하면`
  - `이 카드가 공격하면`
  - `이 카드는 준비 상태로 진입합니다.`
- 영어의 `you`가 있어도 공식 문구에서 주어가 생략된 문형은 그대로 보존할 수
  있습니다. 다만 `내가`를 쓴다면 반드시 플레이어를 뜻해야 합니다.
- 대상이 되는 내 유닛은 보통 `아군 유닛`, 소유·통제 집합은 `내 유닛`으로
  구분합니다.
- 상대 플레이어는 `상대`, 상대가 통제하는 전투 대상은 `적 유닛`으로 씁니다.

### 대상의 도입과 재지칭

- 처음 지정하는 대상은 종류와 수량을 모두 씁니다.
  - `아군 유닛 1명`, `적 유닛 1명`, `주문 1개`, `도구 1개`
- 이미 지정한 대상은 `해당 유닛`, `해당 카드`, `해당 토큰`으로 받습니다.
- 같은 문장 안의 후속 목적어는 문맥이 분명할 때 `그 유닛`, `그 카드`로 받을 수
  있습니다.
- 두 대상을 함께 받으면 `각 유닛`, 각 대상에 같은 수치를 적용하면 `각각`을
  사용합니다.
- 대상 선택이 규칙상 필요하면 `선택합니다`를 생략하지 않습니다.
- 굴절 알림처럼 상대가 표적을 정하는 문구는
  `주문 또는 스킬의 대상으로 선택`으로 씁니다.

## 6. 수량, 수치, 조사와 비용

### 분류사

| 대상 | 분류사 | 예시 |
|---|---|---|
| 카드·룬 | `장` | `카드 2장`, `룬 1장` |
| 유닛·플레이어 | `명` | `아군 유닛 1명`, `상대 1명` |
| 주문·도구·토큰 | `개` | `주문 1개`, `도구 1개`, `토큰 4개` |

- 아라비아 숫자를 사용합니다. `한 장`, `두 명`처럼 수사를 한글로 풀지 않습니다.
- `카드를 2장 뽑습니다`가 아니라 `카드 2장을 뽑습니다`로 씁니다.
- `룬 1장를`과 `토큰 1개을` 같은 잘못된 조사를 사용하지 않습니다.
- 토큰은 `1 위력 신병 유닛 토큰 1개`처럼 위력을 앞에 둡니다.
  `위력이 1인 신병 토큰`으로 풀어 쓰지 않습니다.
- `최대 2명`에 의미가 중복되는 `까지`를 덧붙이지 않습니다.
- 영어의 `N+`는 문맥에 맞춰 옮깁니다.
  - 수량 조건: `유닛 4명 이상`
  - 인쇄된 규칙 기호: `8+ 룬`, `[레벨 6+]`

### 에너지, 힘과 룬

- 에너지, 힘, 룬 카드는 서로 다른 개념입니다.
- 비용은 `에너지 2`, `평정 힘 1`처럼 씁니다. 힘 비용을 `룬 1장을 지불` 또는
  `자원 1`로 바꾸지 않습니다.
- 물리적인 룬 카드를 셀 때만 `룬 N장`을 사용합니다.
- `힘으로 반응하여 에너지 0으로 사용`, `힘 2를 지불`, `힘 대신 에너지 1`처럼
  원문의 비용 종류를 그대로 보존합니다.
- 자원 생성 키워드는 `[추가]`를 사용하며, 자원을 추가하는 스킬에는 반응할 수
  없다는 알림 문구를 보존합니다.
- `[Add]`는 자원 수치 뒤의 `[추가]`로 보존합니다. `[추가]합니다`,
  `추가합니다`처럼 임의의 서술어로 풀어 쓰지 않습니다.

### 헤더 순서

헤더는 다음 순서로 작성합니다.

`[카드명], N 에너지, N 영역 힘, N 위력`

- 카드에 인쇄된 0 에너지도 생략하지 않습니다.
- 다중 영역의 범용 힘은 카드가 허용하는 영역 순서대로 `1 평정/신체 힘`처럼
  표시합니다.
- 주문·도구처럼 위력이 없는 카드는 위력을 넣지 않습니다.
- 전설·전장·기본 룬처럼 비용이 없는 카드는 `[카드명]`만 사용합니다.

## 7. 능력치와 피해 문형

### 위력

- 지속 효과나 현재 조건이 유지되는 동안 존재하는 위력은 `가집니다`로 씁니다.
  - `내가 8+ 룬을 보유하는 동안, 이 카드가 +4 위력을 가집니다.`
  - `이곳에 있는 유닛이 +1 위력을 가집니다.`
- 사건이 발생해 이번 턴 동안 카드가 위력을 얻으면 `획득합니다`로 씁니다.
  - `주문을 사용하면, 이번 턴에 이 카드가 +1 위력을 획득합니다.`
- 다른 대상에게 위력을 주면 `부여합니다`로 씁니다.
  - `이번 턴에 아군 유닛 1명에게 +3 위력을 부여합니다.`
- `얻습니다`, `획득하세요`, `부여하세요` 같은 표현을 사용하지 않습니다.
- 위력 감소 하한은 확인된 문형인 `1 위력까지 감소할 수 있습니다`를 사용합니다.

### 피해

- 피해는 `N의 피해를 입힙니다` 순서로 씁니다.
  - 올바름: `유닛 1명에게 6의 피해를 입힙니다.`
  - 잘못됨: `피해 6을 입힙니다.`
- 추가 피해는 `N의 추가 피해`로 씁니다. `추가 N의 피해`로 쓰지 않습니다.
- 여러 대상에 같은 피해를 주면 `최대 2명의 유닛에게 각각 6의 피해를
  입힙니다`처럼 씁니다.
- 여러 대상이 서로 피해를 입히면
  `각 유닛이 자신의 위력만큼 서로에게 피해를 입힙니다`로 씁니다.
- 모든 대상, 전투 중인 대상, 한 전장에 있는 대상 같은 범위를 생략하지 않습니다.

## 8. 카드 행동과 영역 이동

- 카드의 `play`는 `사용합니다`로 씁니다.
- `When you play me`는 `이 카드를 사용하면`으로 씁니다.
- 토큰도 `사용합니다`로 씁니다.
  - `이곳에 1 위력 신병 유닛 토큰 1개를 사용합니다.`
- `I enter ready`는 `이 카드는 준비 상태로 진입합니다`로 씁니다.
- `kill`은 `처치합니다`, `banish`는 `추방합니다`, `discard`는 `버립니다`로
  구분합니다.
- `Return [target] from your trash to your hand`는
  `[대상과 수량]을 내 폐기장에서 내 손으로 되돌립니다`로 씁니다.
  - 대상과 수량을 먼저 씁니다: `유닛 1명을`, `주문 1개를`, `도구 1개를`,
    `최대 2장의 [키워드] 카드를`.
  - 출발지와 목적지의 소유 주체를 모두 보존해 `내 폐기장에서 내 손으로`라고
    씁니다. `내 폐기장에 있는 … 손으로`처럼 목적지의 `내`를 생략하지 않습니다.
  - 선택 효과라면 `되돌릴 수 있습니다`, 강제 효과라면 `되돌립니다`로 원문의
    선택 가능성을 보존합니다.
  - 손으로 돌려보내는 동작은 `되돌립니다`이며 `귀환시킵니다`가 아닙니다.
    `귀환`은 유닛을 기지로 보내는 규칙 동작에만 사용합니다.
- `recall`은 `귀환시킵니다`, 일반 `move`는 `이동시킵니다`로 구분합니다.
- 귀환 알림 문구가 있으면 `(유닛을 기지로 보냅니다. 이는 이동이 아닙니다.)`를
  보존합니다.
- `channel`은 `전개합니다`로 씁니다.
  - `룬 1장을 탈진 상태로 전개합니다.`
  - `룬 1장을 탈진한 상태로 전개할 수 있습니다.`
- `탈진 상태로`와 `탈진한 상태로`는 모두 공식 카드에서 확인됐습니다. 실물
  문구를 한 형태로 일괄 치환하지 않습니다.

### 비용으로 카드 자신을 탈진할 때

- 비용의 출처를 생략하지 않고 `이 카드를 탈진:`으로 씁니다.
- `탈진:`만 단독으로 쓰거나 `탭:`으로 바꾸지 않습니다.
- 비용과 효과의 순서, 쉼표, 콜론, 대시, `[반응]` 위치는 확인된 인쇄 문구를
  보존합니다.

## 9. 시점, 조건, 선택 가능성과 처리 순서

### 고정 시점 알림 문구

- `[행동] (내 턴 또는 결전 시 사용합니다.)`
- `[반응] (주문 및 스킬이 처리되기 전을 포함해 시점에 관계없이 사용합니다.)`

`자신의 턴 또는 결전 중`, `해결되기 전을 포함해 언제든` 같은 과거 문형으로
바꾸지 않습니다.

### 조건과 선택

- `may`의 선택 가능성을 `할 수 있습니다`, `선택할 수 있습니다` 등으로 반드시
  보존합니다.
- 강제 효과를 선택 효과로 바꾸거나 선택 효과를 강제로 바꾸지 않습니다.
- `if`, `while`, `during`, `until`, `for the rest of this turn`의 지속 범위를
  생략하지 않습니다.
- `otherwise`는 `그렇지 않을 경우`, 비용을 실제로 지불한 분기는
  `그렇게 할 경우`처럼 앞 조건과 연결합니다.
- 대체 효과의 `instead`, 사망 시점의 `when`, 나중에 발생하는 `이후 이번 턴에`를
  문장 순서대로 보존합니다.
- `이후`, `대신`, `그렇게 하면`, `그렇지 않을 경우` 같은 연결어를 임의로
  제거하지 않습니다.
- 서로 다른 조건에서 발생하는 독립 트리거를 `그리고`로 묶어 하나의 조건처럼
  만들지 않습니다. 각각의 시점과 조건을 별도 문장으로 보존합니다.
- 영어 문장을 효과 메타데이터나 요약 목록으로 재구성하지 않습니다.

## 10. 키워드와 알림 문구 작성법

- 키워드명, 비용, 수치는 대괄호 안에 보존합니다.
- 키워드 수치가 없으면 임의로 `1`을 붙이지 않습니다.
- 같은 카드에서 여러 키워드가 결합된 알림 문구는 실물의 결합 방식을 그대로
  보존합니다.
- 알림 문구의 주어가 일반 문형과 다르게 보이더라도 확인된 실물 문구를 임의로
  고치지 않습니다.

### 확인된 주요 알림 문구

- `[개입] (이 카드는 전장에서 전장으로 이동할 수 있습니다.)`
- `[탱커] (이 카드는 전투 피해를 가장 먼저 배정받습니다.)`
- `[맹공] (이 카드가 공격자인 동안 +1 위력을 획득합니다.)`
- `[통찰] (이 카드를 사용하면, 내 주 덱 맨 위 카드를 확인합니다. 해당 카드를
  재활용할 수 있습니다.)`
- `[굴절] (상대가 이 카드를 주문 또는 스킬의 대상으로 선택하려면 힘을 지불해야
  합니다.)`

### 원문에 없는 `하다` 금지

영어 원문이 동사 없이 키워드만 지시하면 한국어에도 `하다`를 덧붙이지 않습니다.

- 단독 지시: `[예측].`
- 후속 처리: `[예측 2] 후 카드 1장을 뽑습니다.`
- 알림 문구: `([예측 2]: 내 주 덱 맨 위의 카드 2장을 확인합니다. …)`

`[예측]을 합니다`, `[예측 2]를 한 후`, `[예측]하려면` 같은 형태를 사용하지
않습니다. 이 규칙은 다른 단독 키워드 지시에도 동일하게 적용합니다.

자원 키워드도 같은 원칙을 적용합니다.

- `Energy 1 [Add].` → `에너지 1 [추가].`
- 잘못된 형태: `에너지 1을 [추가]합니다.`, `에너지 1을 추가합니다.`

`Mighty`는 일반 형용사가 아니라 상태 키워드입니다. 모든 규칙상 용례를
`[강력]`으로 표시합니다.

- `a [Mighty] unit` → `[강력] 유닛`
- `while I'm [Mighty]` → `이 카드가 [강력]인 동안`
- `becomes [Mighty]` → `[강력]이 되면`
- 알림 문구: `(유닛은 위력이 5 이상인 동안 [강력]입니다.)`

`Counter`는 카드 본문, 선택지, 상태 표시에서 모두 `차단`으로 통일합니다.
`무효화`, `무효화됨`은 사용하지 않습니다.

### Vendetta 키워드 문형

`Empower`는 키워드명과 행동을 구분합니다.

- 키워드명: `[강화]`
- `Empower me.` → `이 카드를 강화합니다.`
- `Empower a unit.` → `유닛 1명을 강화합니다.`
- `When I become [Empowered]` → `이 카드가 [강화됨] 상태가 되면`
- `an [Empowered] unit` → `[강화됨] 상태인 유닛`

`Empowered`를 `[강화]된`, `강화 상태`, `[강화 완료]`로 바꾸지 않습니다. 카드
본문에서는 상태임을 분명히 해야 할 때 `[강화됨] 상태`로 씁니다.

`Disempower`는 `강화 해제`를 하나의 규칙 행동으로 사용합니다.

- `Disempower me.` → `이 카드를 강화 해제합니다.`
- `Disempower a unit that's [Empowered].` → `[강화됨] 상태인 유닛 1명을 강화
  해제합니다.`
- 비용: `이 카드를 강화 해제하고, …`

`Flow`는 키워드명과 비용 모두 `흐름`으로 씁니다.

- 키워드명: `[흐름]`
- `Flow cost` → `흐름 비용`
- `play this from your trash for its Flow cost` → `흐름 비용을 지불하고 이 카드를
  내 폐기장에서 사용할 수 있습니다.`
- `Then banish it.` → `이후 이 카드를 추방합니다.`

`Burn`과 `Burn Out`은 서로 다른 규칙 행동입니다.

- `Burn 3.` → `[소각 3].`
- `They Burn 1.` → `그 플레이어가 [소각 1].`
- 알림 문구: `(소각하려면, 주 덱 맨 위에서 지정된 수만큼 카드를 폐기장에
  놓습니다.)`
- `Burn Out` → `소진`
- `burns out` → `소진됩니다.`

`소각`을 `소진`, `추방`, `버리기` 또는 `폐기`로 바꾸지 않습니다. `소진`도
`소각됨`이나 `번아웃`으로 쓰지 않습니다.

`Skip`은 대체 효과인 규칙 행동이므로 `생략`, `제외`보다 `건너뛰기`를
사용합니다.

- `Skip your Draw Phase.` → `내 뽑기 단계를 건너뜁니다.`
- `skip the scoring procedure` → `득점 절차를 건너뜁니다.`

## 11. 기본 룬

- 오리진 한국어판 기본 룬에는 효과 문장이 인쇄되어 있지 않습니다.
- 엔진이 사용하는 에너지 생성·재활용 규칙 설명을 한국어 카드 효과 문구로
  표시하지 않습니다.
- 격노, 평정, 정신, 신체, 혼돈, 질서 룬과 각 일러스트 변형은 `koText: ""`,
  `printedTextEmpty: true`를 사용합니다.
- 룬의 엔진 동작은 유지합니다. 표시 문구를 비우는 것이 규칙 동작을 제거한다는
  뜻은 아닙니다.

## 12. 카드명, 전설과 고유명사

### 전설 카드

전설 카드명에는 챔피언 이름을 중복하지 않습니다. 챔피언 이름은 유형 줄에 둡니다.

- `어둠의 아이` / `전설, 애니`
- `우주 검사` / `전설, 마스터 이`
- `광명의 소녀` / `전설, 럭스`
- `데마시아의 힘` / `전설, 가렌`

챔피언 유닛은 카드명에 챔피언 이름을 유지합니다.

- `마스터 이, 사색`
- `럭스, 광명`
- `가렌, 강건`

시그니처 카드는 유형 줄에 챔피언을 표시합니다.

- `시그니처 주문, 럭스`
- `시그니처 유닛, 애니`

### 확인된 오역 방지 고유명사

- `Mountain Drake` → `대지의 드래곤` (`바람 드래곤` 아님)
- `Eclipse` → `월식` (`일식` 아님)
- `Eclipse Herald` → `월식의 전령`

고유명사가 불확실하면 사전이나 일반적인 직역만으로 확정하지 않고 사용자에게
확인합니다.

## 13. 문체와 금지 형식

- 효과 문장은 존댓말 평서형 `-합니다`로 작성합니다. `-하세요`, `-하라` 같은
  명령형을 사용하지 않습니다.
- `유닛들`, `유닛들에게` 같은 불필요한 복수 접미사를 사용하지 않습니다.
- 카드 문구에 `주문 효과:`, `지속 효과:`, `활성화 능력:` 같은 자체 분류를
  덧붙이지 않습니다.
- `대상 · 수치 · 조건`처럼 효과를 메타데이터 목록으로 요약하지 않습니다.
- 카드의 문장 순서를 바꾸거나 같은 효과를 한 문장으로 합치지 않습니다.
- 이미 확인된 알림 문구를 더 친절해 보이는 설명으로 다시 쓰지 않습니다.
- 공식 실물의 문장부호와 줄바꿈을 확인할 수 있으면 그대로 보존합니다.

### 자동 감사에서 금지하는 대표 형태

- `쇼다운`, `매복`, `탭:`, `메인 덱`, `버림 더미`, `파워`, `장비`, `채널`
- `[은신]`, `[방벽]`, `[사냥]`, `인내`, `빈 전장`
- `피해 3`, `추가 1의 피해`, `카드를 2장 뽑습니다`
- `유닛 토큰 1명`, `룬 1개`, `주문 1장`, `도구 1장`
- `소환`, `내려놓`, `파괴`, `휴지통`, `쓰레기통`, `얻습니다`
- 번역되지 않은 영문 문장 조각

## 14. 세트별 적용

### `OGN`·`OGS`

- 한국어 실물 카드로 확인된 문구는 글자, 대상, 수량, 조사와 알림 문구를 그대로
  보존합니다.
- 증명의 전장 스타터에 들어 있는 오리진 카드는 스타터 포함 여부를 실제 제품
  구성과 대조합니다. 다른 오리진 카드를 임의로 스타터 공식 문구의 근거로 삼지
  않습니다.

### `SFD`·`UNL`·`VEN`

- 세트 번역은 등록 카드 전체를 빠짐없이 포함해야 합니다. 현재 기준 수량은
  `SFD` 221장, `UNL` 219장, `VEN` 166장입니다.
- 정식 한국어판 근거가 없는 동안에는 이 문서의 문형을 적용한 프로젝트 번역이며
  `비공식 번역` 표시를 유지합니다.
- 오리진 문체와 다른 임의의 번역체를 새로 만들지 않습니다.
- 정식 한국어판 문구가 제공되면 세트별 번역 파일의 이름, 헤더, 유형 줄과 본문을
  함께 교체하고 출처를 기록합니다.
- 원문의 키워드 표기만 있는 곳에 `합니다`, `한 후`, `하려면`을 추가하지 않습니다.
- `VEN` 카드명과 전체 카드 본문은 비공식 번역으로 유지하되, 공식 한국어 패치
  노트와 FAQ에서 확인된 키워드 및 규칙 용어에는 `확정` 표기를 적용합니다.

## 15. 수정 절차와 검증

한국어 번역을 추가하거나 수정할 때 다음 순서로 작업합니다.

1. 카드 번호와 실제로 표시되는 세트별 번역 항목을 확인합니다.
2. 영어 원문의 대상, 수량, 비용, 시점, 선택 가능성, 처리 순서를 분해해
   대조합니다.
3. 한국어 실물 근거가 있으면 사진 또는 사용자 전사를 글자 단위로 보존합니다.
4. `koName`, `koHeader`, `koTypeLine`, `koText`를 함께 확인합니다.
5. 확정도에 맞춰 `officialTextSource`, `비공식 번역`,
   `printedTextEmpty`를 설정합니다.
6. 같은 문형의 다른 카드를 전체 검색해 동일한 오류를 함께 수정합니다.
7. 회귀 테스트와 자동 감사 규칙을 추가하거나 갱신합니다.
8. `npm run check:no-ai`를 실행합니다.

### 자동 검증과의 대응

- `scripts/audit-korean-terms.mjs`: 필수 용어, 금지어, 분류사, 비용 혼동과 문체
- `scripts/audit-ko-translations.mjs`: 영문 잔존, 의미 동작, 누락 표식과 메타데이터
- `scripts/audit-card-logic.mjs`: 영문 규칙, 한국어 의미, 실행 효과의 일치
- `tests/i18n.test.mjs`: 공식 전사, 헤더, 룬 무문장, 고유명사와 번역 문형 회귀

문서와 코드가 다르면 둘 중 하나만 임의로 따르지 않습니다. 공식 근거를 다시
확인하고, 확정된 결과에 맞춰 이 문서와 자동 검증을 같은 변경에서 함께 갱신합니다.
